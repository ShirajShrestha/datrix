# Datrix v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the single-feed NewsIntel app into Datrix: 14 selectable categories, image cards, free-LLM summaries, installable PWA, and a customizable morning Web Push notification, with no accounts.

**Architecture:** One daily ingest (GitHub Actions → Next.js route) pulls RSS + Guardian + GNews/MediaStack per category, tags/scores/dedupes, stores a ~25-per-category pool in Mongo, and summarizes only new articles through a Groq → Gemini → extractive chain. The browser keeps all preferences in localStorage and asks `/api/articles?categories=…`. The only server-side per-device record is a push subscription; a 15-minute GitHub Actions tick sends each one at its local time.

**Tech Stack:** Next.js 16 App Router, TypeScript, Tailwind 4, Mongoose, `rss-parser`, `web-push`, Serwist (`@serwist/next`), Vitest.

**Spec:** `docs/superpowers/specs/2026-10-18-newsintel-v2-design.md` (read it first; this plan only decides what the spec leaves to the builder).

## Global Constraints

- Free services only; no paid API. Never put secrets in code, docs, workflow files, or commits. The Guardian key is already in `.env.local` as `GUARDIAN_API_KEY`.
- No user accounts, login, or user table. Preferences live in `localStorage` key `datrix_prefs`. Saved articles keep the existing key `newsintel_saved_articles` (renaming would wipe the reader's saves).
- Category slugs exactly: `ai, technology, business, world, geopolitics, politics, law, science, health, environment, sports, entertainment, education, society`. Legacy slugs `tech` → `technology`, `economy` → `business`.
- Default notification time `08:00`, customizable; stored per subscription with its IANA timezone (owner's is `Asia/Kathmandu`, UTC+5:45). Never hard-code the timezone in the sender.
- Pool: top 25 per category. Articles expire 30 days after `publishedAt`. LLM summaries only for articles with no stored summary, batched 5–10 per call.
- Summary provider order: Groq → Gemini Flash → extractive. Model names come from env (`GROQ_MODEL`, `GEMINI_MODEL`); keys `GROQ_API_KEY`, `GEMINI_API_KEY`.
- Push env: `VAPID_PUBLIC_KEY`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`. Cron auth: `Authorization: Bearer ${CRON_SECRET}`.
- One scheduler: GitHub Actions. `vercel.json` crons removed.
- App name is **Datrix** in all user-visible text. UI/UX redesign is out of scope (spec phase 8).
- Tests: Vitest, files in `src/**/__tests__/*.test.ts`. Pure logic gets unit tests; React components and routes are verified by running the app (use the `run` skill) and stated checks.
- Commit messages are Conventional Commits and end with the Co-Authored-By trailer from the session's attribution instruction.
- Do not commit `.env*`. Do not push or deploy unless the owner asks.

## Review Focus

Spec-implied failure modes that are most likely to bite, each pinned by a test in the named task:

1. A feed returns HTTP 500, invalid XML, or empty → ingest still completes with the other sources (Task 6, Task 9).
2. Article has no image anywhere → placeholder is used, ingest does not fail or stall on slow `og:image` fetches (Task 7).
3. `localStorage` holds corrupted JSON, unknown slugs, or legacy slugs `tech`/`economy` → prefs sanitize instead of crashing (Task 12).
4. Reader deselects every category → feed shows all categories, not an empty page (Task 12).
5. Push: invalid timezone string, same-day double tick, or a 404/410 from the push service → no throw, no duplicate send, dead subscription deleted (Task 16, Task 17).
6. LLM returns fewer items than sent, extra items, or non-JSON → missing items get the next provider/extractive, none lost (Task 10).
